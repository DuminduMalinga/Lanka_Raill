# CeylonGO data (Supabase)

Project: **Lanka_Rail** (`prcmausakhaswaidsamz`). The Flutter app reads it
through `lib/data/` (`SupabaseCeylonRepository` + Riverpod providers).

```
supabase/
  migrations/   schema, in the order applied to the live project
  seed/         reference data, timetable, photos, notices — safe to re-run
  data/         source files + build_seed.py that generates seed/02_*.sql
  templates/    empty CSVs with the right headers for Table Editor imports
```

Run order on a fresh project: all `migrations/` in order, then
`seed/01_reference_data.sql`, `seed/02_timetable_and_photos.sql`,
`seed/03_announcements.sql`, `seed/04_stations_routes_destinations.sql`,
`seed/05_wikimedia_thumb_host.sql`.

## What is loaded

| Data | Rows | Source |
|---|---|---|

| Stations | 42 | Seed; coordinates approximate (`source = 'seed-unverified'`) |
| Trains | 65 | seat61.com timetable tables (page updated 10 June 2026) |
| Stop times (`train_stops`) | 321 | Same; **main stations only**, `verified_at` null |
| Seat classes | 189 | Same (reserved / unreserved classes per train) |
| Destinations, tags, nearest stations | 13 / 18 / 15 | Seed |
| Photos | 13 destination covers, 32 stations, 10 trains, 49 gallery | Wikimedia Commons (CC BY / BY-SA / CC0 / Free Art License), credit stored per photo |

Not loaded (no reliable source found): station facilities, fares, on-board
facilities, distances. The app hides those sections or says they're not listed.

The official railway.gov.lk PDFs for Yarl Devi and the Jaffna Night Mail
(every stop) were **not** loaded: their times differ completely from seat61's
June 2026 table (likely pre-cyclone), so the seat61 rows were kept. The
curated full-stop data is in `data/extra/trains.py` if an official current
timetable confirms it.

`seed/05_wikimedia_thumb_host.sql` moves every photo URL to
`thumb.wikimedia.org`: `upload.wikimedia.org` answers app requests with
429 Too Many Requests, which left photos blank in the app.

`migrations/20261123165833_feedback.sql` adds `feedback` (Help & feedback
screen): insert-only for app users, readable in the dashboard.

`migrations/20261124102832_feedback_rate_limit.sql` limits feedback to 5 per
hour per signed-in user and 30 per hour for anonymous senders (SQLSTATE
`FB429`).
`migrations/20261125113328_feedback_fair_limits.sql` replaces the shared
anonymous pool with 5 per hour per sender (identified by Cloudflare's
`cf-connecting-ip`, stored only as a daily-changing one-way hash) plus a
200 per hour overall cap, serialises parallel requests with an advisory lock,
and limits `app_version` to 32 characters.

`migrations/20261125113651_avatars_one_file_per_user.sql` lets a user write only
`avatars/<uid>/avatar` (the app overwrites it and puts a version in the saved
URL), so one account can no longer pile up files. The app also checks the
photo's real type from its first bytes before uploading. Bucket-level limits
(2 MB, JPEG/PNG/WebP) still rely on the type the client reports, which a
modified client could forge for its own single file.

`migrations/20261124102923_search_journeys_limits.sql` makes `search_journeys`
reject codes outside 2-8 characters and return at most 50 options; its
running time is capped by Supabase's role timeouts (3 s anon, 8 s signed in).

## Edge functions

`functions/delete-account` (deployed to the live project, JWT verification on)
lets a signed-in user delete their own account from Profile > Delete account.
It reads the caller from the session token, removes `avatars/<uid>/`, then
deletes the auth user; foreign keys cascade to `profiles` and the favourites
tables, and `feedback.user_id` is set to null (feedback is kept, unlinked).
If removing the photo fails the account is left in place so the user can retry.
Deploy changes with the Supabase CLI (`supabase functions deploy delete-account`)
or the dashboard. It uses the `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`
variables Supabase provides to every function; no secret needs to be added.

## Why the timetable is from seat61

The official sources were unavailable when this was built (23 Nov 2026):
- railway.gov.lk "Train Schedule" page: "Page Under Development".
- eservices.railway.gov.lk schedule search: TLS certificate invalid.
- seatreservation.railway.gov.lk only lists trains with seats left and is
  bot-protected.

seat61.com's tables were copied exactly (`data/seat61_timetable_2026-06-10.json`).
Train **6** was left out because the source lists it leaving Elle (10:25)
before Badulla (10:45). seat61 also notes hill-country services are still
affected by 2025 cyclone damage — e.g. Podi Menike (#1005) is shown ending at
Ella. **Check against an official SLR timetable before relying on it**, then:

```sql
update train_stops set verified_at = now() where train_id = (select id from trains where number = '1005');
select * from timetable_issues;   -- soft warnings: long gaps where only main stations are listed
```

## Updating the timetable

Edit `data/seat61_timetable_*.json` (or add another source file), then:

```
python supabase/data/build_seed.py      # regenerates seed/02_timetable_and_photos.sql
```

and run the generated SQL in the SQL editor. For one-off corrections use the
CSV path: fill `templates/timetable_import.csv`, import it into
`timetable_import`, then `select * from import_timetable();`.

## Photos

Photos are linked from Wikimedia Commons (`thumb.wikimedia.org`) rather than
copied into Storage, so the licence page stays one tap away
(`*_source_url`). The app shows each photo's credit (author · licence). To use
your own photos instead, upload to the `destination-photos`,
`station-photos` or `train-photos` buckets and update the URL columns.

The empty `photos` bucket is a leftover and can be deleted from Storage.

## Auth

Password rules are set in Authentication > Providers > Email (not in SQL): minimum
length 10 and "Letters and digits" required. The app applies the same rule
(`lib/features/auth/data/password_rules.dart`); keep the two in step. Passwords
themselves are hashed by Supabase Auth (bcrypt) and never stored by the app.
Still off: leaked-password protection (Pro plan only) and CAPTCHA (needs hCaptcha
or Turnstile keys).

Email/password, Google and Facebook sign-in use Supabase Auth. Redirect URL
`lk.hashtag.lankarail://login-callback/` must be listed under
Authentication → URL Configuration (it is used for sign-up confirmation and
password reset links too). Favourites (`favorite_*`) and `profiles` are
per-user with RLS.
